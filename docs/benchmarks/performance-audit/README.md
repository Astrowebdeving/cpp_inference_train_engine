# Performance audit records

See the [guide](../../performance_audit.md) for the results and limits. [comparison.json](comparison.json) contains the measured reports, stage mapping, source hashes and verification link. Individual directories retain commands, raw samples, exact generated tokens, logs and their original environment records.

The baseline binary and source were copied before modifying this implementation. The work then progressed through aligned reuse, removal of single-request reuse, unequal-row scatter, and the final automatic shape policy. `sources` preserves each engine stage; each report's hashes identify its exact harness version, which may live in another stage directory. The final snapshot corresponds to the current implementation. The historical stages are evidence, not alternative recommended defaults.

The final serving comparison is [serving-auto-128](serving-auto-128/comparison.json): actual native and vLLM-Metal HTTP processes, tested serially with vLLM first, 128-token inputs, 64 outputs, one warmup and five bursts at concurrency 1/4/8. The [1,024-token vLLM prefill budget trial](serving-packed-vllm-1024-budget/comparison.json) tests another configuration. That number is a scheduler budget, not the prompt length. The [long-context](serving-packed-1024/comparison.json) and [mixed-length](serving-packed-mixed/comparison.json) trials used ungated scatter; the automatic policy was added after the small-batch regressions were measured.

The [Muon report](muon/comparison.json) includes full-model first-update gates and reversed-order training trials. Its cold one-step parity timings include initial optimizer compilation and are not the performance results; use the warmed `chain-first`, `gram-first`, `gram-repeat` and `chain-repeat` measurements.

The engine ablations use fixed decode input tokens to separate cache execution from autoregressive token divergence. [Aligned batches](cache-engine.json), [unequal batches of eight](cache-engine-ragged.json), [small unequal batches](cache-engine-unequal-small.json), and [automatic versus forced policy](cache-engine-auto-policy.json) preserve all samples. The [projection microexperiment](projection-micro.json) did not support adding gate/up packing. The [process-boundary profile](baseline-profile.json) is a diagnostic sample, not a repeated speed result or kernel-level GPU trace.

The saved experiment scripts show exactly how the measurements and numerical gates were made. They contain the recorded workspace paths and output locations; select fresh outputs when adapting them. The supported reusable entry points are `tools/compare_serving.py`, `mini_mla_bench`, and the verification commands in the guide. Large tensor exports, binaries, environments and model weights remain in ignored workspace artifacts; their hashes and pinned model revision are recorded.
